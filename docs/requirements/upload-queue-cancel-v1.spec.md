# 上传队列取消与逐文件进度 v1

## 范围

在既有文件工作台上传面板增加用户取消与确认完成数量，复用串行 `VaultClient.upload`、AbortSignal、上传 Key 与幂等键生成器。不新增 API、后台任务、存储/数据库接口、SDK 或配置，不实现跨刷新续传、Multipart 恢复或字节级上传进度。

## 契约

- 展示本轮已确认完成文件数/总数；仅收到成功响应才计入完成，不把文件被加入队列或开始发送计为成功。
- “取消上传”请求 AbortController 中止当前客户端请求，并停止后续尚未发送文件。停止请求未结束时仍禁用重入、前缀编辑和文件队列编辑；不会提前开启第二轮并行请求。若 transport 不响应 abort，面板保持“正在停止”直到请求完成或切换上下文。
- 取消后移除确认成功项，保留当前未确认项和未发送项；迟到成功响应可计为已确认完成，但仍不能发送下一文件。非取消错误沿用保留失败项和待发送项的行为。
- 取消不是服务端回滚，当前对象可能已经保存。完成停止后刷新当前文件列表供用户核对，并明确提示核对后再重试；不自动删除、覆盖补偿或重试。
- 对同一 client、File 对象和目标 Key 的显式重试复用幂等键；client 切换使用新的工厂。REST 写操作按 `Idempotency-Key` 头选择既有中间件，没有本轮新增“启用”开关。记录可能仍在处理中、过期/清理或完成记录失败，重试可返回 409；保留现有 hash-body/TTL 配置语义，不承诺取消后的 exactly-once 或绝不产生新版本。
- client/初始目录切换或卸载时中止当前请求、停止旧队列，并丢弃旧进度、提示和刷新回调；新上下文不接收旧队列文件。文件视图 all/mine 不改变上传目标，不新增按视图的写入规则。
- 保持既有文件数量限制、认证 Header、Content-Type、Key 校验和幂等请求参数；取消不增加 CRUD/ACL/删除能力，也不把浏览器上传链路宣称为端到端有界内存流式。

## 验收

前端覆盖顺序/确认计数、取消前已成功项、当前请求 abort、transport 迟到成功、停止期间防重入、保留队列与幂等键重试、普通错误、client/目录/卸载隔离和 StrictMode。使用真实 VaultClient 加 mock fetch 验证 signal、凭据和原请求契约。

执行既有 REST 上传/幂等回归、`make web-check` → `make build` → `make web-smoke`、`make check` + `python3 cli.py accept`。浏览器冒烟仅证明嵌入应用加载；服务端取消时点/崩溃可靠性、外部身份/存储与大文件性能不属于本轮专项验收。
