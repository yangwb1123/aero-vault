**几点补充思考：**

| 方向 | 补充观察 |
|------|---------|
| **方向一：Admin/Data Plane 分离** | 如果采用双端口方案，Helm chart 需要新增 Service + NetworkPolicy + Ingress 资源。此外，考虑在数据端口返回 404 的同时，建议 admin 端口返回 405 Method Not Allowed（而非 404）用于数据路径——减少探测信息与协议一致性之间的权衡 |
| **方向二：对象访问审计** | 方案 B+（service 层 + `skip_audit` context 值）需要注意 context 值传递的安全性——如果 handler 可以注入 `skip_audit=true` 就能绕过审计。建议改用 `skip_audit` 只对内部已知 context 类型（如 `reconcileCtx{}`）生效 |
| **方向三：MCP 管控** | stdio 模式增加 credentials 是个好思路，但要考虑向后兼容性：现有 MCP 客户端（Claude Desktop 等）发送的 initialize 消息中不会有 credentials 字段。建议降级策略是"无 credential = 只读 + 限速更严格"而非完全拒绝 |
| **方向四：硬配额** | 三阶段协议的 Phase 2 → Phase 3 间隔中如果进程崩溃，残留预占记录需要 reconciler 清理。建议 `reserved_at` 的过期阈值设为 `max(5min, storage_timeout + 10s)` 以减少误清理 |
| **方向五：动态配置** | 优先关注"配置字段分类"——你提到的"黑/白名单"思路很好。建议再加一层 `Safety` 接口：某些配置变更（如关掉 auth）即使语法正确也应该被拒绝 |
