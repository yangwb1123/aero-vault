## 1. Scope

Every existing audit-governance e2e exercises only **API-initiated writes**: `cmd/server/governance_e2e_test.go` (M1–M6 + activation-gate tests) and `internal/api/s3compat/audit_governance_e2e_test.go` (GAP-1) all drive `svc.Put` (`file.created`). The **quarantine emit path** (`ScanObjectByID` → `QuarantineObjectByID`) is the repo's only **system-origin** (`system:antivirus`) governance emitter, and it splits across two governance paths — the audit row is written by `SoftDeleteObjectByIDWithEvent` direct SQL (bypassing the wrapped `RecordAudit`), so under governance the admin fact (`action=file.delete`, `detail=av_infected`) exists **only** via the T-4 gap reconcile, while the `file.deleted` fact arrives via the `InsertEvent` atomic path. `internal/antivirus` has **zero** `auditgovernance` references anywhere (grep-verified), and its AC-1a/AC-2 harness drains only the *events* outbox.

This spec adds, in `internal/antivirus` only, **test-only** requirements (zero production/schema/dependency footprint) that pin the direction's three supplied acceptance checks against the real quarantine wiring: EICAR → `virus_scan` job → `ScanObjectByID` → quarantine, through the production-shaped governance assembly (`WrapRepository` → `bus.WithRepository` → `svc.WithEventSink` → `WithObjectController`, mirroring `cmd/server/main.go` / `cmd/server/workers.go:26-28`).

**Out of scope:** direction 2 (gap-capture staleness observability — new metric/gauge) and direction 3 (T-4 deterministic-fact-ID pin for the quarantine shape) of the same analysis; any production code change; any schema/migration change; any telemetry change; any change to the existing antivirus tests (`antivirus_test.go` AC-1a/AC-2/AC-3a/AC-4, `hardening_test.go`, `perf_test.go`, `truncation_test.go`); modification of the `cmd/server` or `s3compat` e2e files; new env knobs.

### REQ-1 — Quarantine-origin dual-path e2e: exactly 2 governance rows, both terminal-delivered (AC-a)

Object soft-deleted (`GetObjectByID` → `DeletedAt != nil`); `audit_log` exactly 1 row (actor `system:antivirus`, action `file.delete`, target `default/eicar.txt`, detail contains `av_infected`); `event_outbox` exactly 2 due facts (deleted@1.1 + notify@1.1) — the existing AC-1a pins, re-asserted under governance (quarantine semantics unchanged by the wrapped repo).
2. **Pre-start snapshot (relay not started):** `SELECT COUNT(*) FROM audit_governance_outbox` == **1** — only the atomic `file.deleted` row exists: `origin_kind='file'`, `action='file.deleted'`, `fact_kind='file'`, `origin_id = (SELECT id FROM object_events WHERE object_id=? AND type='deleted')`, `attempts=0`, `delivered_at_ns=0`, `failed_at_ns=0`, `available_at_ns>0`, empty claim. The admin row does **not** exist yet (born on the first reconcile tick inside `rt.Start`).

4. **Both terminal-delivered:** waitFor each row `delivered_at_ns>0 AND failed_at_ns=0 AND attempts==1 AND claim_owner=='' AND last_error==''` (the M1 predicate shape).

## 4. Decisions & non-goals

- **D1 — The new tests live in `internal/antivirus`**, the direction's module. The pin point is the quarantine emit path itself (job → `ScanObjectByID` → `QuarantineObjectByID`), and the package already owns the job-pool harness (`newScanPool`, `enqueueScan`, `waitForJobDone`) and the events-outbox helpers. This makes the first `auditgovernance` import in the package — which is precisely the coverage gap the direction identifies.
- **D2 — Harness mirrors the cmd/server/s3compat e2e idioms read-only**: config literal + `auditgovernance.New` (not `config.Load()` — the env chain is already pinned by `cmd-server-audit-governance-production-assembly-e2e-v1.spec.md`), wrapped repo, `bus.WithRepository`, `svc.WithEventSink(bus)`, relay deliberately unstarted for deterministic pre-start snapshots, `waitFor`/`quiesce` idioms (never `waitFor` on a negative — A6), raw sqlite assertions with `?` placeholders (I1).
- **D3 — Reuse package helpers** (`newScanPool`, `enqueueScan`, `waitForJobDone`, `claimDueFacts`, `EICAR`, `quietLogger`) to keep the new file well under the 500-line gate (~350 estimated). The `govReceiver`-equivalent (202-echo / 409 / 422 modes, `/token` OAuth2 form, `wait_for=ledgered` query pin, `{"receipt":{...}}` 202 envelope) is a ~60-line local copy (the `cmd/server` receiver is package `main`, not importable).
- **D4 — The direction's AC-(c) is decomposed into two sub-scenarios** (capture-off: zero rows; activation gate: `AuditGovernanceUnboundBacklogError` at `auditgovernance.New`). The literal conjunction ("zero governance rows, startup apply fails") is **not jointly satisfiable**: `unboundGovernanceBacklog` scans only `audit_governance_outbox` (`audit_governance_binding.go:107-128`), so with zero rows the apply succeeds. The decomposition preserves the direction's intent 1:1 — the fail-closed gate exists precisely so that an *existing* backlog can never be silently orphaned by a binding removal, and the capture-off behavior pins that an *unbound* quarantine is correctly unmonitored rather than queued.
- **D5 — Zero production footprint:** no production code, no schema, no migration, no telemetry, no `go.mod` change (stdlib + existing imports only, I6); sqlite+local FS, zero network beyond `httptest` (I5/CI baseline).
- **Non-goals:** direction 2 (gap-capture staleness metric) and direction 3 (T-4 fact-ID recomputation pin for the quarantine shape) of the same analysis; fact-ID determinism is already pinned for the atomic path by `wantFactID` (cmd/server) and the s3compat e2e — REQ-1 asserts row identity by `origin_kind/action/origin_id` mapping, not by recomputed SHA-256; no change to the `cmd/server` or `s3compat` test files; no audit_log/events-outbox behavior change (the existing AC-1a/AC-2 pins are re-asserted, not modified).
