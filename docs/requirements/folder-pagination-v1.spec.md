# 目录分页 v1

## 最小范围

延续文件工作台与“我的文件”视图，解决目录列表只读取第一页、超过 1000 个可见对象后无法继续发现子目录的问题。复用 FileService 的 ListWithOptions，不新增目录表、领域服务、Storage/Repository 接口、迁移或依赖。

## REST 契约

`GET /v1/folders?path=...&view=all|mine&marker=...&limit=...`：

- 保留 `path` 规范化与 view 规则，继续执行桶 ListBucket policy、租户状态、可信归属及读取授权；分页不是权限旁路。
- `marker` 与文件列表一样是上页返回的对象 Key；`limit` 限制本页读取的可见对象数，而非直接目录项数。省略、非法整数、非正数或超过 1000 时沿用 FileService 的 1000 默认上限。
- 响应保留 `prefix/items`，新增 `has_more/next_marker`。没有下一页时 marker 为空；最后一页以 has_more=false 结束。
- 子目录由当前页可见对象推导，不暴露无权读取对象的名称或游标；同一目录可能出现在多页，消费者按 type+name 去重。一次读取不承诺列举全部目录。
- 即使本页没有子目录，或只有当前路径的 marker 对象，也必须保留继续分页能力；不得把尚未读完解释为“没有子目录”。
- path、view、身份或租户改变后，客户端重新从空 marker 开始。对象列表非快照，分页期间内容变化可能导致重复或缺项，刷新重新列举。
- 保持 no-store 及现有 CORS/凭据/租户 Vary；运行时 OpenAPI 同步描述分页语义。

## 工作台

- 目录独立于文件列表分页；“我的文件”的目录续页保持 mine。
- 合并重复目录，不重复展示同一文件/目录项；显示仍未读完提示及“加载更多目录”。缺失、重复或循环的游标不继续请求，提供重新加载入口。
- 加载下一页失败时保留已加载目录并显示错误，可重试同一页；禁止并行重复加载。
- 目录、视图、client 改变或初始列表刷新后，旧续页结果不得混入当前列表；卸载后不更新状态。
- 保持 mine 视图不提供递归目录删除；不改变上传、删除、分享或默认 ACL。

## 验收

SQLite/local HTTP 测试覆盖跨页重复目录、超过 1000 对象、只有 marker 的页面、终页游标、mine、Deny、停用租户与 provider 故障；前端测试覆盖续页参数、去重、错误重试、防重复请求与 scope/刷新/卸载隔离。

执行 `make web-check` → `make build` → `make web-smoke`、`make check` 与 `python3 cli.py accept`，更新嵌入产物。浏览器冒烟只验证嵌入加载；大规模性能、真实外部存储与外部身份联测不属于本轮验收。
