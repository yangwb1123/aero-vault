### REQ-1 — The alert expression threshold is derived from the same constant as the config default (acceptance a)

The `AuditGovernanceBacklogDegraded` expr threshold must equal `shipped-default MaxLagSeconds / 2` (450 for 900), and the test that asserts it must **derive** the expectation from the config loader through `BacklogAlertThresholdSeconds()` — never a hand-written literal — so either side drifting alone fails CI.

- *Pin (rule side, shipped):* `TestAlertsYMLAuditGovernanceExprParity` (`cmd/server/readyz_drill_test.go:381-419`) — `wantExpr = "expr: audit_governance_backlog_age_seconds > " + strconv.Itoa(cfg.AuditGovernance.BacklogAlertThresholdSeconds())` (`:388-389`) with `cfg` from `config.Load()` under `AUDIT_GOVERNANCE_ENABLED=false` + `AUDIT_GOVERNANCE_MAX_LAG_SECONDS=""` (empty → `getEnvInt` falls back to the shipped default `:114`); `os.ReadFile` on `deploy/prometheus/alerts.yml` (`:391`); exactly two `expr: audit_governance_` rules file-wide (`:399-401`); block-scoped assertions (`:408-418`): `wantExpr`, `OR audit_governance_degraded == 1`, `for: 10m`, `severity: warning`, `/readyz stays 200`. Stdlib-only (`os`/`filepath`/`strings`/`strconv` — I6).
- *Pin (derivation site, shipped):* `BacklogAlertThresholdSeconds()` (`internal/config/config_audit_governance.go:42-50`) — `MaxLagSeconds / 2`, floor semantics, value receiver, zero I/O. Pinned by `TestAuditGovernanceBacklogAlertThresholdDerived` (`internal/config/config_audit_governance_test.go:87-138`): shipped default via loader (`900/2`, env-neutralized), struct-form table `{900, 1800, 901}` in **derived arithmetic** (`1800/2`, `901/2` — never a literal `450`; the `901` case pins floor vs ceil), ordering hardening `threshold < maxLag` for all three, zero-value → 0.
- *Pin (default side, shipped):* `TestAuditGovernanceMaxLagDefaultIsTwiceBacklogAlertThreshold` (`internal/config/config_audit_governance_test.go:64-85`) — asserts 900 through `loadAuditGovernanceConfig()` with identical neutralization.
- *Pin (no second literal, shipped):* `TestNoExecutable450LiteralOutsideAlertsYml` (`cmd/server/readyz_drill_test.go:540-583`) — `\b450\b` scan over `cmd/`, `internal/`, `sdk/go` `.go` files with comments and string literals stripped; the only executable `450` in Go is gone (the former dead `const alertLagThresholdSeconds = 450` and the former `metrics_test.go` fixture `450`→`137` are both already removed).

## 4. Decisions & non-goals

- **D1 — Static alerts.yml stays; the pins are the single-sourcing mechanism.** The direction's "generated rule or templated annotation" suggestion is satisfied by *pinning the literal to a derivation* (parity test + accessor + default pin + 450-ban), not by templating/generating the rule file. A generation step would add deploy-tooling surface for no behavioral gain (effort 2 direction); rejected. Consequence, accepted and documented: a per-operator maxLag override does not shift the static age arm (it fires at the shipped 0.5×ratio); the config-true signal under override is the `degraded == 1` OR arm at `age > configured maxLag` — this is the documented contract in `alerts.yml:176-182` and the accessor doc, and it bounds both failure modes the direction names (premature paging: fires at ≤ maxLag, never at 0.25×; silent SLA miss: the terminal backlog still alerts at maxLag).
- **D2 — Go test beats CI grep.** The proposed "test/grep" is superseded by `TestAlertsYMLAuditGovernanceExprParity` under `go test ./...` (Makefile:18, CI `.github/workflows/ci.yml`), with no new grep rules, no Makefile edit, no YAML dependency (I6).
- **D3 — Env neutralization is load-bearing.** Both parity pins set `AUDIT_GOVERNANCE_MAX_LAG_SECONDS=""` so the expectation is computed from the *shipped default*, not an ambient operator override — an override cannot silently re-anchor the static comparison (REQ-1).
- **D4 — Scope mapping.** The direction is labeled for module `internal/reconcile` but touches no reconcile code; the design/implement stages must not add reconcile-side work (sweeper-event capture and the D1 read-path drill are sibling directions of the same analysis — `internal-reconcile-7a29db11.json` directions 1 and 2 — explicitly out of scope here).
- **Non-goals:** alerts.yml content beyond what the pins assert (severity/`for`/description wording), the `AuditGovernanceEnabledUnbound` drain companion rule (`alerts.yml:202`), per-config (non-default) alert thresholds, gauge naming/scrape surface, config surface/bounds, migrations, `internal/reconcile` behavior.
