# 回收站批量恢复 v1

## 最小范围

在文件工作台回收站增加勾选与“恢复所选”。逐项复用现有 `POST /v1/files/{key}/restore`，不新增服务端批量接口、领域模型、数据库迁移或 SDK 方法。不实现回收站清空、硬删、目录递归恢复或任意历史版本恢复。

## 行为契约

- 仅处理用户显式选中的已加载文件；分页全选只选已加载对象，不默认操作整个回收站。同一 Key 去重后只发送一次。
- 恢复前确认数量，逐项串行发送，避免无界并发。仍由 FileService 独立执行 restore 授权、租户状态、Blob 存在性、配额及同名文件冲突检查。
- 恢复语义保持现状：按 Key 恢复最近用户删除的对象，不复活历史 version tombstone，不覆盖已有同名活跃对象。它不是跨文件事务，也不新增恰好一次承诺。
- 一项失败不阻止后续项；记录每项恢复成功或 API 错误。成功项取消选择，失败项保留选中以供重试；显示成功/失败摘要与前几项失败原因。
- 恢复期间禁用选择及同范围内重复恢复。切换目录、回收站模式、mine/all 或 client，以及卸载时，停止后续尚未发出的请求，不将旧结果、提示或刷新混入新范围。
- 已发送的请求可能继续执行，范围切换不是服务端回滚；网络/后置计量失败也可能使结果不确定，刷新确认实际状态后再重试。再次恢复已有活跃对象仍返回冲突，不把 412 自动记为成功。
- 回收站只提供恢复与取消选择，不显示批量标签、删除或永久删除。单对象恢复继续可用。

## 验收

前端测试覆盖勾选/已加载全选、确认取消、全成功与部分失败、错误原因、失败项重试、串行/去重、mine 与分页选择、重复提交防护及目录/视图/client/卸载隔离。SQLite/local HTTP 测试验证既有单项恢复的授权 Deny、停用租户、同名冲突与配额拒绝不被工作流绕过。

执行 `make web-check` → `make build` → `make web-smoke`、`make check` 与 `python3 cli.py accept`，更新嵌入产物。外部身份/存储联测、跨 Blob/数据库/计量原子性及大规模吞吐不属于本轮验收。
