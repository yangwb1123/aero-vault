## 3. Requirements (contract + pin; all satisfied by the shipped worktree except RG-1)

Each REQ states the behavior contract the D1 drill requires and names the pin that makes it testable. The implement stage's job is to verify the pins exist and pass and to add RG-1's missing pin — no other production delta is expected.

### REQ-1 — The audit-governance read path is time-bounded (2s per probe, 2s at the seam)

`Runtime.Ready`'s two store probes (`HasPendingDrainingAuditGovernance`, `OldestPendingAuditGovernance`) run under `storeProbeTimeout = 2 * time.Second` (`runtime.go:26`, `:251-253`); `readyzHandler` calls `extra.Ready(probeCtx)` with the same 2s budget used for `repo.Ping` and the storage probe (`http.go:97-111`).

- *Pin (boundedness, deterministic lower bound):* `TestRuntimeReadyDegradedSentinel` (`runtime_ready_test.go:176-204`) — hanging stub returns only after the ctx deadline; `Ready(context.Background())` returns with elapsed ∈ [1s, 5s]. `TestReadyzAuditGovernanceDegradedDrill` (`readyz_drill_test.go:444-466`) — same bound through the real handler.
- *Pin (seam bound for non-degrading checkers — the fail-closed half of the same contract):* `TestReadyzExtraProbeTimeout` (`readyz_drill_test.go:161-175`) — a generic extra that returns `ctx.Err()` after the deadline yields 503 within [1s, 5s] (a checker without degrade semantics stays fail-closed; the audit runtime *does* degrade, REQ-2).

### REQ-2 — Probe timeout/cancel degrades, never 503

`errors.Is(err, context.DeadlineExceeded) || errors.Is(err, context.Canceled)` on either probe → Warn log, `recordDegraded(true, 0)` (age unknown), `Ready` returns **nil** (`runtime.go:255-259`, `:268-272`, classifier `:231-233`). At the seam this surfaces as HTTP 200 with `{"ok":true,"degraded":true,"backlog_age_seconds":0}` (`http.go:118-122`).

- *Pins:* `TestRuntimeReadyDegradedSentinel` (`runtime_ready_test.go:176`) — nil, `Degraded()==true`, `BacklogAge()==0`; subtest `c3-pre-canceled-ctx` of `TestRuntimeReadyFailClosedOnGenuineStoreError` (`:206-252`) — pre-canceled ctx returns immediately (< 1s), nil + degraded (the `context.Canceled` fork); `TestReadyzAuditGovernanceDegradedDrill` (`readyz_drill_test.go:444`) — 200, never 503, marker body, age 0.
- *Residual (RG-1):* the shipped pins wedge **both** probes (`scriptedStore.hang`, `runtime_ready_test.go:33-77`; `hangingAuditStore`, `readyz_drill_test.go:426-437`), so `probeAndRecord` always hits the drain-probe timeout fork first (`runtime.go:254-259` before `:266-272`). The acceptance's literal shape — *only* `OldestPendingAuditGovernance` times out — is never exercised. **Add** a per-probe hang flag (e.g., `backlogHang` alongside `hang`) to `scriptedStore` and a subtest: drain probe healthy, backlog probe blocks → `Ready()==nil`, `Degraded()==true`, `BacklogAge()==0`, elapsed ∈ [1s, 5s]. Effort ≈ 10 lines in `runtime_ready_test.go`; the production fork `runtime.go:268-272` is already correct and needs no change.

### REQ-3 — Genuine (non-timeout) store errors stay fail-closed: 503, unchanged

Non-context store errors on either probe → hard error from `Ready` (`runtime.go:260-261`, `:273` — error strings `"audit governance drain lookup failed"` / `"audit governance backlog lookup failed"`), and `readyzHandler` maps any `extra.Ready` error to 503 `runtime dependency unavailable` (`http.go:110-111`). Drain-in-progress stays a hard error (`runtime.go:263-264`). This is the direction's "store errors fail-closed" branch **preserved by design**, not a regression — the D1 contract degrades *timeouts*; genuine failures remain eviction-worthy.

- *Pins:* `TestRuntimeReadyFailClosedOnGenuineStoreError` (`runtime_ready_test.go:206`) — c1 drain-error and c2 backlog-error subtests assert the exact error strings and `Degraded()==false` (a genuine error is never recorded degraded); `TestReadyzImmediateExtraError` (`readyz_drill_test.go:179-190`) — non-deadline extra error → 503 immediately (< 1s, not delayed by the wrap); `TestReadyzDrainStill503` (`readyz_drill_test.go:258-279`) — draining binding + pending fact → 503 at the seam; `TestReadyzImmediateStorageError` (`http_test.go:115-146`) — storage-probe analog.

### REQ-4 — Gauge read path: bounded by construction, and a wedged store read is never silent

The backlog-age and degraded-flag gauge callbacks read only the runtime cache — zero store I/O per scrape (`build.go:101-118`); the store read that fills the cache is bounded by `storeProbeTimeout` inside `probeAndRecord` (REQ-1), fed by the run loop once per poll cycle (`runtime.go:319-323`). On a probe timeout the pair is `(degraded=1, age=0)` — the wedge is **non-zero on the degraded gauge** even though the age is unknown — and the alert expr fires via the OR arm (`alerts.yml:186`). On a genuine store error the probe returns before recording, so the cache **retains the last recorded pair** (a transient read error never zeroes a live wedge value; `runtime.go:319-324`).

- *Pins:* `TestReadyzAuditGovernanceDegradedDrill` (`readyz_drill_test.go:444`) — wedge: ageGauge=0 ∧ degradedGauge=1; `TestAlertsYMLAuditGovernanceExprParity` (`readyz_drill_test.go:381-438`) — the expr threshold is **derived** from `config.Load()`'s `MaxLagSeconds/2` (450 for the shipped default 900; `internal/config/config_audit_governance.go:49-50` `BacklogAlertThresholdSeconds()`, default `:114`) and the `OR audit_governance_degraded == 1` arm is required — a regression dropping the arm fails CI; `TestNoExecutable450LiteralOutsideAlertsYml` (`readyz_drill_test.go:540-576`) — no executable 450 literal outside alerts.yml; `TestAuditGovernanceBacklogAgeGaugeSurfaceInScrape` (`internal/telemetry/metrics_test.go:171`) and `TestAuditGovernanceDegradedGaugeSurfaceInScrape` (`:192`) — both series surface in the scrape; `TestAuditGovernanceMaxLagDefaultIsTwiceBacklogAlertThreshold` (`internal/config/config_audit_governance_test.go:64`) — the ×0.5 default side pinned at its owner; `TestReadyzDeadLetteredBacklog200AndGaugeZero` (`readyz_drill_test.go:288-364`) — the cache-fed callback reports real ages (≥ 2s backdate) after one priming probe, i.e. the read is the cache, not a silent constant zero.
- *Freshness:* `TestRuntimeRunLoopRefreshesCacheWithoutReadyCalls` (`runtime_ready_test.go:348-395`) — with zero `Ready()` calls the loop flips the cache degraded on a 16s-backdated backlog and healthy after a test-controlled age restore, within one poll cycle; `TestRuntimeRunLoopSurvivesWedgedStore` (`:397-414`) — the loop keeps cycling through wedged probes and recovers.

### REQ-5 — Read-path and delivery-path ctx-error classifications are separate

Delivery-path classification (`isPermanentDeliveryError`, `relay.go:87`) is untouched: `context.DeadlineExceeded` remains **transient** there (pinned by `relay_terminal_test.go:225`). The read path uses its own classifier `isProbeCtxError` (`runtime.go:231-233`). No shared classifier; changing one path's semantics cannot leak into the other.

- *Pins:* `TestIsPermanentDeliveryErrorClosedList` (`relay_terminal_test.go:200-243`, `DeadlineExceeded` at `:225`) + REQ-2's timeout pins (read path). The two are separate tests in separate files.

### REQ-6 — Regressions held: maxLag flip still degrades; terminal rows still excluded from lag

(a) A pending backlog older than `maxLag` degrades (Ready nil + `Degraded()==true` + age exposed) — never a hard error, never 503; (b) dead-lettered (`failed_at_ns != 0`) rows remain excluded from `OldestPendingAuditGovernance` (predicate `delivered_at_ns=0 AND failed_at_ns=0`), so a fully dead-lettered backlog reports no pending and never blocks readiness.

- *Pins:* `TestRuntimeReadyDegradesOnBacklogLag` (`runtime_test.go:618-670` — the direction's cited `:412-471` test, relocated; seed shape preserved, maxLag 4s, Ready nil, degraded, drain still hard-fails `:662-670`); `TestReadyzBacklogLagDegradesNot503` (`readyz_drill_test.go:212-250`) — seam: 200 with the exact marker body for an 8s-backdated row (> maxLag 4s, 2× margin, deterministic backdate — no sleeps); `TestRuntimeBacklogAgeZeroWhenAllTerminal` (`runtime_ready_test.go:254-317`, lease-fenced Claim+Fail); `TestRuntimeBacklogAgeZeroWhenNoPending` (`runtime_test.go:676-699`, empty store); `TestReadyzDeadLetteredBacklog200AndGaugeZero` phases 0–1 (`readyz_drill_test.go:288-364`, empty + dead-lettered at the seam with gauge 0); `TestReadyzGroupDegradedComposition` / `TestReadyzGroupReadyFailPropagates` / `TestReadyzGroupEmpty` (`http_test.go:215-267`) — group aggregation semantics.

## 4. Decisions & non-goals

- **D1 — Bound is a package constant, not config.** `storeProbeTimeout = 2s` (`runtime.go:26`) mirrors `readyzProbeTimeout` (`http.go:53`) with a cross-reference comment; no new env knob, no config surface (sibling spec decision D1).
- **D2 — Degraded is a cache sentinel, not a live query.** `Degraded()`/`BacklogAge()` are zero-I/O cache getters (`runtime.go:213-226`); the probe runs in `Ready()` and the run loop. This is what makes the drill deterministic (blocking stubs, no store contention) and scrapes hang-proof.
- **D3 — Gauge callbacks are cache-fed (zero store I/O), which dominates the direction's "gauge err→0 masks the wedge" acceptance.** The direction assumed the gauge queries the store per scrape and zeroes on error; the shipped design removes the per-scrape store read entirely (S7), and the (bounded) store read happens only in the probe path. Acceptance (b) is satisfied via this stronger mechanism; REQ-4's pins make the property testable.
- **D4 — Wedge signal = degraded-flag gauge + alert OR arm, not the age gauge.** Age is unknown on timeout (`recordDegraded(true, 0)`), so the age gauge reads 0 by design; the degraded gauge is the non-silent signal (`TestReadyzAuditGovernanceDegradedDrill` pins ageGauge=0 ∧ degradedGauge=1, `TestAlertsYMLAuditGovernanceExprParity` pins the OR arm).
- **D5 — Two-layer seam contract with the fail-closed branch preserved.** `readyzHandler` guarantees the 2s budget for any extra checker (`http.go:110-111`); the audit runtime additionally *self-degrades* on ctx errors so its contribution is 200 + marker, while genuine store errors and drain-in-progress keep 503 (fail-closed, unchanged — the direction's "store-error branch" is preserved, not removed). Both halves pinned (REQ-3).
- **Non-goals (do not expand scope):** direction 1 of the same analysis (reconcile sweeper mutations emit no governance facts — lifecycle/retention/orphan deletions), direction 3 of the same analysis (450s-alert threshold single-sourcing — already shipped by the sibling run and pinned by `TestAlertsYMLAuditGovernanceExprParity`/`TestNoExecutable450LiteralOutsideAlertsYml`; this spec only *uses* that pin as the "alert still fires" evidence), billing-runtime readiness (contributes `false`/`0` through the group, `http.go:36-38`), `readyzProbeTimeout`/storage-probe/database-probe branch behavior, alert severity/`for`/description content beyond what the pins already assert, drain semantics, config surface, migrations, and any new test beyond RG-1 plus verifying the pins in §3.

## 6. Risks & gates

- **Pin-drift risk (low):** the acceptance pins live in four packages (`internal/auditgovernance`, `cmd/server`, `internal/telemetry`, `internal/config`); the `make check` gate (`gofmt -l`, `go build ./...`, `go vet ./...`, `go test ./...`, 500-line production-file check) covers them all. Any refactor of `probeAndRecord`, the cache pair, or the marker body breaks the named pins.
