## 3. Requirements

### REQ-1 — WebDAV-surface governance harness (T-3 vehicle)

The test harness `newWebdavRelayHarness` (`dav_relay_test.go:37-90`) MUST gain a governance wiring mode that mirrors `cmd/server/main.go:70-82`: open the raw repo, build `auditgovernance.Runtime` via `auditgovernance.New` over `repo.(auditgovernance.Store)` with a harness-shrunk config (the `runtimeConfig` pattern of `runtime_test.go:40-47`: poll 10ms, batch 10, claim TTL 3s, backoff 1s→2s), `Start` it, wrap the repo (`auditgovernance.WrapRepository`), install the wrapped repo on the bus (`bus.WithRepository`), and hand the wrapped repo to `service.NewFileService` — then register teardown `runtime.Close()` (LIFO, before `repo.Close`). The harness MUST expose a governance receiver (httptest server answering `/token` with a bearer token and the fact POST path — `governancePath = "api/v1/events"`, `internal/auditgovernance/model.go:19` — with a per-case responder, the `terminalSink` shape of `relay_terminal_test.go:166-192`).

- **AC-1.1 (wiring shape).** The harness wires `WrapRepository → bus.WithRepository → svc.WithEventSink(bus)` in main.go order; a WebDAV PUT + DELETE over the harness enqueues governance rows on the **file** path. *New test infrastructure.*
- **AC-1.2 (exactly one row per event).** With a healthy receiver (202 + `{duplicate:false, conflict:false, status:"ledgered"}` receipt), PUT + DELETE yields exactly one `audit_governance_outbox` row per bus event (`origin_kind='file'`, `fact_kind='file'`, `action="file.created"` / `"file.deleted"` — `factFromEvent` sets `"file."+event.Type`, `facts.go:42`), each delivered (`delivered_at_ns>0`), each POSTed exactly once; the in-tx audit row (`Detail="hard"`) enqueues **no** governance row. *New.*
- **AC-1.3 (config validity).** Harness governance config honors C-6 (`ClaimTTL > 2×HTTPTimeout`; 3s > 2×1s) and the `MaxBackoffSeconds >= InitialBackoffSeconds` validation (`config_audit_governance.go:240`), self-honored like the existing relay options comment (`dav_relay_test.go:12-16`). *New.*

### REQ-2 — T-3 at the webdav harness: permanent classes terminal within ≤1 attempt (AC preserved 1:1)

With the REQ-1 harness and a governance receiver answering **409** (then **422**, then a **malformed receipt** — three isolated table rows, each its own httptest server + tempdir DB, the `runTerminalCase` shape of `relay_terminal_test.go:55-97`): every `audit_governance_outbox` row enqueued by the WebDAV mutations MUST reach `failed_at_ns>0` within ≤1 attempt (`attempts==1`), MUST be POSTed exactly once (no re-POST), MUST never be re-claimed, MUST be absent from `OldestPendingAuditGovernance`, and MUST be excluded from `Ready()`'s lag computation.

- **AC-2.1 (≤1 attempt, terminal).** For each row of `{http409, http422, malformed-receipt (202 + non-JSON body)}`: `SELECT failed_at_ns, attempts, last_error FROM audit_governance_outbox` → `failed_at_ns>0` AND `attempts==1` AND `last_error` non-empty (409/422 → `httpStatusError` text; malformed → `ErrInvalidReceipt` text). *New (webdav surface; the repo-level twin is `assertTerminalState` `relay_terminal_test.go:126-146`).*
- **AC-2.2 (never re-claimed — `audit_governance_claim.go:38`).** After the observe window (`posts` stable for ≥ 2× the harness max backoff, the `observeWindow` pattern `relay_terminal_test.go:99-103`): `ClaimAuditGovernance(ctx, owner, token, revision, 10, time.Minute)` returns 0 rows. *New.*
- **AC-2.3 (absent from lag + Ready).** `OldestPendingAuditGovernance(ctx)` → `ok==false`; `runtime.BacklogAge(ctx)` → `ok==false`; `runtime.Ready(ctx)` → `nil` (`runtime.go:151-185` — terminal rows excluded). *New.*
- **AC-2.4 (exactly one POST per row).** Receiver POST counter == number of enqueued rows (PUT+DELETE ⇒ 2 rows ⇒ 2 POSTs), and no growth during the observe window — the same "exactly once, absolute" counting discipline as `TestWebDAVDelete_CompositionL1L2` (`dav_relay_test.go:221-236`). *New.*

### REQ-3 — Cumulative transient retry cap: 300s bounded retry window (production change)

A fact whose delivery fails with **transient-only** errors (e.g., a receiver answering 500) MUST go terminal once the **cumulative retry window** exceeds the configured cap — `MaxBackoffSeconds`, default **300s** (`config_audit_governance.go:65`) — with `last_error` retained; until then it MUST keep being rescheduled with `boundedBackoff` (per-attempt delay ≤ the same cap). This is the "瞬态有界重试 cap 300s" half of contract item 1 and the acceptance's 500-receiver clause. Terminal means the full dead-row semantics: `failed_at_ns>0`, never re-claimed, absent from `OldestPendingAuditGovernance`, excluded from `Ready()`/`BacklogAge`, pruned only by `CleanupFailedAuditGovernance` after retention.

- **AC-3.1 (persistence of the window anchor).** A new migration pair **0044** (both dialects — I2: new file, applied 0039/0042/0043 untouched) adds a first-attempt timestamp column (`first_attempt_at_ns INTEGER NOT NULL DEFAULT 0`, naming per design) to `audit_governance_outbox`; it is set once on the row's first claim and never reset by retry/lease-reclaim; the pending partial-index predicate (`delivered_at_ns=0 AND failed_at_ns=0`, 0043) is **unchanged**. *New production change.*
- **AC-3.2 (window decision, pure + pinned).** The terminal decision is a pure function of (first-attempt time, now, window) — unit-tested with injected times, stdlib only (I6): `now - firstAttempt > window` ⇒ terminal; `==` boundary stays transient (strictly greater). The window equals the configured `MaxBackoffSeconds` (default 300s — pinned by reading the default in `config_audit_governance.go:65`). *New.*
- **AC-3.3 (e2e: 500 receiver → terminal after the window).** At the webdav harness with a 500-answering receiver and the harness-shrunk window (`MaxBackoffSeconds=2s` in the REQ-1 config ⇒ cumulative window 2s): the row keeps being re-POSTed while `now - firstAttempt <= window`, then goes terminal — `failed_at_ns>0`, `attempts >= 2`, `last_error` contains the 500 status text, POSTs stop growing thereafter, `ClaimAuditGovernance` returns 0 rows, `OldestPendingAuditGovernance` → none, `Ready()==nil`. Bounded test time (~4s: claim at t=0, re-POST at ~1s, terminal at ~3s). *New.*
- **AC-3.4 (defaults at production config).** With the production default window (300s) the same decision function yields terminal only after the cumulative window — pinned by the AC-3.2 unit test (no 300s wall-clock wait in CI). *New.*
