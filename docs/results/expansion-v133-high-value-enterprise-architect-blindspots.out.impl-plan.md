### 方向重排与顺序建议

根据项目约束（重构优先、`make check` 门禁、测试 ≥ 50%），建议的实施优先级为：

1. **方向四（统一授权） → 最快见效、影响面最大**
   - 从 REST handler 提取 `checkBucketPolicy` 为通用 `Authorizer` 接口
   - 修复 REST 侧 `DefaultBucket` 硬编码问题（文档指出的关键事实修正）
   - 填补 WebDAV 零认证、MCP 零授权的安全缺口
   - **预估 7 任务 / 18h → 3 天内完成核心，5 天内全协议一致**

2. **方向二（不可变审计） → 独立高价值**
   - 哈希链 + 签名 + 验证 API + 导出，完全独立
   - **预估 5 任务 / 16h → 4 天内完成，与方向四并行**

3. **方向一（数据主权路由） → 最大架构变更**
   - 需要 StorageRouter 抽象 + 迁移 + 双写模式
   - 路由核心接口（T001-T003）4 天，迁移功能（T006）3 天
   - **阻塞方向三，建议在方向四/二完成后启动**

### 关键风险标识

- **R1（高）**：在线迁移数据一致性 → 双写模式 + checksum 校验
- **R2（中）**：审计哈希链并发性能 → 异步哈希计算 + `prev_id` 引用
- **R4（中）**：多后端 GC 扇出 → 对象元数据记录 `backend_id` + 扇出安全网
- **R7（高）**：WebDAV 无标准认证 → Basic Auth 映射到 API Key
